Robot Framework with Python 3.10+. Write Robot Framework test suites in the .robot format and use SeleniumLibrary (robotframework-seleniumlibrary) for browser automation, unless the task's structureNotes asks for another library (for example the Browser library).
Structure: Page Object Model, expressed with resource files. Put test suites under tests/ (one .robot file per test case, one test case named exactly after the test case title), and put every page in resources/pages/<name>_page.resource with its locators in a *** Variables *** section and its actions as keywords in a *** Keywords *** section. Put shared setup and teardown keywords (open and close the browser) in resources/common.resource. Test suites import the resource files with the Resource setting and only call page keywords and assert; they contain no raw locators.
Use the sections *** Settings ***, *** Variables ***, *** Test Cases *** and *** Keywords ***, with [Documentation] and [Tags] (priority and type) on each test case. Express every step as a keyword call and add an assertion for each expected result. Use explicit waits such as Wait Until Element Is Visible and never a fixed Sleep. Read the base URL and credentials from environment variables with the %{NAME=default} syntax (for example %{BASE_URL=http://localhost:3000}) and never hardcode real credentials.
Custom Python keyword libraries are optional: only add libraries/<name>.py when a keyword cannot be written in Robot syntax.
Always include requirements.txt (robotframework and robotframework-seleniumlibrary) and a short README.md that says how to run the tests (pip install -r requirements.txt, then robot tests/). Follow the folder structure and naming rules in the task's structureNotes when they are given.
